# 维护与安全边界

## 登记与信任模型

姓名为自助填写，不校验真实身份；同名设备会进入同一身份。MAC 可被仿冒，私有随机 MAC 会产生新记录。工具不取代 WPA、访客 VLAN、AP 隔离或受控管理网络。

登记请求只能通过表单 POST；字段、长度、UTF-8、同源头部均受检查。浏览器未发送 Origin 时仍兼容门户内嵌浏览器，不能把此兼容性当成完整 CSRF 认证机制。后端把请求来源 IP 与当前邻居表、受控 AP 关联表交叉核对，拒绝离线地址、其他网络来源以及黑名单设备；客户端不能提交要操作的 MAC。

管理员 RPC 受 LuCI/rpcd ACL 保护。控制器地址和密钥不会返回只读接口。注册表、临时快照与审计含姓名、MAC、IP 和管理员备注，均按私有资料管理；对外报告错误时先脱敏。系统 logger 仍可能按路由器自身策略保留操作类别和 MAC，门户不负责清除外部日志。

流量卸载策略由用户选择。默认保留系统设置，优先避免给整机增加转发负担；代价是已卸载连接可能绕过拉黑、出口切换和许可到期。严格模式仅检查并要求系统卸载关闭，不主动改系统防火墙；检查的是配置开关，管理员仍需确保修改已应用，且没有其他快速转发插件绕过门户。原理见 [Linux 内核 flowtable 文档](https://docs.kernel.org/networking/nf_flowtable.html)。

## 数据与故障边界

持久准入登记配置为 `/etc/config/portal`。写操作使用同一把锁、独立暂存目录，校验完成后再原子替换。发现其他工具尚未提交的 portal 修改时拒绝覆盖；请先确认并提交或撤销外部修改。

登记、拉黑等操作保存配置后应用 nft 原子事务。应用失败会明确报错并保留可重试的登记配置；旧规则可能仍在，管理员应修复后重试。无线持久禁连还涉及 `/etc/config/wireless`，两个配置文件与内核运行状态无法形成跨系统事务，错误信息会区分保存和应用阶段。不要在后台并发直接编辑这些文件。

审计是有限的运行期操作记录，最多两份约 128 KiB，重启丢失。设备观察历史为独立有界持久数据，每 15 分钟合并保存，不能当作完整接入历史或审计合规存档。登记首次时间与首次在线观察时间不同。租约或 STALE 邻居不证明在线；未知端口/AP 查询失败显示未确认。字段与丢失窗口见 [设备观察与历史](设备观察与历史.md)。

## 安装、升级与卸载

首次安装默认关闭。包登记自己的 firewall4 include 和五分钟缺表检查；不自动刷新全机网络。正常升级保留 UCI conffile，不调用完全卸载清理。安装框架可能按已有配置启动服务，因此变更前仍需有管理恢复通道。

从非公开旧版迁移时，先停用旧版并备份 `/etc/config/portal`、`wireless`、`firewall`、`uhttpd`、`network` 及代理覆写。旧版可能修改过主 uhttpd、额外 IP、crontab 或程序目录备份，这些不能靠新版安装自动判断所有权。逐项恢复后显式填写接口、监听地址和可选控制器设置。不要直接复制旧版整个 `/etc/portal` 或生成文件覆盖新版程序。

旧版无线禁连没有门户所有权标记时，新版解封不会删除无法确认归属的 MAC 过滤条目；管理员须对照备份手动处理。公开版只撤销自己加上 `portal_owned_macs` 标记的条目，保留原有列表和过滤模式；遇到原有白名单模式会拒绝添加持久禁连。

卸载基础包会先将登记配置备份为 `/root/identity-portal-backup-时间.uci`，权限 0600，正常停止观察器并另备份设备历史，再清理自己的无线禁连、服务、nft 表、定时任务和 firewall4 include。历史文件不会被主动清空。清理无线禁连可能短暂影响无线连接。发现 wireless 或 firewall 有外部未提交修改时会拒绝卸载清理，避免误提交其他配置。

包卸载不清理管理员自己的策略、主 uhttpd 或网络配置。外部仍引用生成文件时，仅留下当次启动期间可用的中性占位文件；**重启后文件不会持久存在**，所以应先从 Mihomo 中移除集成规则再卸载。

## 实机验收

在正式控制工作网络前，使用一个测试 AP 和独立管理入口逐项验证：

1. 启用、停止、重启、firewall4 重载后，HTTP、DNS、DHCP、IPv6 邻居发现及管理入口符合预期。
2. 未登记 → 登记 → 拉黑 → 解封 → 移除记录，白名单与归属组合均符合状态表。
3. 随机 MAC、多 IPv6 地址、睡眠唤醒、AP 切换、DHCP 换租后，无旧地址错误放行。
4. 如用指定出口，验证 TCP/UDP 和 IPv4/IPv6 的实际出口；关闭出口、停止 Mihomo、停止同步进程，观察许可撤销和到期。
5. 无线持久禁连与解封保留原有过滤项，接口离线时仍能清理门户所有权记录。
6. 软件升级、卸载和恢复备份均保持独立管理通道可用。

本版未宣称已在所有驱动、透明代理模式或低端硬件完成这些实机验证。构建通过和 `nft -c` 只能证明打包及规则可接受性，不能代替真实流量验收。
