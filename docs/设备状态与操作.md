# 设备状态与操作

## 四个独立维度

| 字段 | 含义 |
| --- | --- |
| `identity` | 设备归属的身份记录；必须实际存在才视为已登记 |
| `trusted` | 白名单；值为 1 时可以免登记 |
| `policy` | `block` 表示黑名单，优先于其他准入条件；通常为 `allow` |
| `egress` | `normal` 沿用原有网络策略；`wifi-only` 为指定 Mihomo 出口，名称为历史兼容字段，不限定物理 WiFi 上联 |

显示状态按“黑名单 → 已登记 → 白名单 → 未登记”派生。已登记设备也可以带白名单标记，该标记在解除身份归属后继续有效。正常出口表示门户不附加出口限制，不承诺绕过网络本来的防火墙或代理策略。

## 门户启用时的处理

下表描述经过门户防火墙规则的流量。默认允许保留系统卸载；已经进入软件/硬件快速转发的连接可能不再经过这些检查，因此后续拉黑、出口切换和许可到期不能保证及时生效。需要严格执行访问撤销时，先关闭并应用系统卸载设置，再选择 `offload_policy=require-off`。这两个选项均不会替用户改变系统卸载开关。

| 设备条件 | 普通上网 | Mihomo 不可用时 | 登记与本机访问 |
| --- | --- | --- | --- |
| 黑名单，无论身份、白名单、出口 | 阻断受控 AP 的入站流量 | 仍阻断 | 不允许自行登记解封 |
| 已登记或白名单，正常出口 | 交给原有网络策略 | 不受门户分流依赖影响 | 原有网络策略 |
| 已登记或白名单，指定出口 | 当前 MAC 与源地址同步确认后，TCP/UDP 交给 Mihomo；IPv4、IPv6 均支持 | 收回访问许可，保持设置 | 保留 DHCP、必要邻居发现、DNS 与门户；不开放其他路由器管理端口 |
| 未登记，全局 `unauth_policy=drop` | 阻断 | 仍阻断 | 仅保留登记所需通信 |
| 未登记，全局 `unauth_policy=wifi-only` | 同步确认后仅允许 IPv4 TCP/UDP 交给 Mihomo；普通 IPv6 流量阻断 | 收回访问许可 | 保留登记；拦截本机管理及常见私有 IPv4 目的地址 |

在受控桥上，未正常放行设备的跨端口二层转发也被阻断；无线驱动内部的同 AP 转发需开启客户端隔离。指定出口不会开放任意 IP 协议，只有 TCP/UDP 进入分流；DHCP、必要 IPv6 邻居发现和本机 DNS 属于基础服务例外，不承诺 DNS 走设备指定出口。

分流状态按周期检测，并非瞬时探测。每次确认后向内核授予有期限的 MAC+IP 许可，默认最长 40 秒；同步进程停止也会自行到期。正常检测失败会主动清空许可。这个期限限制的是门户集合中的许可，不是已卸载连接的最大存活时间。新 IPv6 地址必须等下一次确认；首次同步或规则重建期间，经门户检查的受限流量暂时不能普通上网。

## 哪些操作改变状态

| 操作 | 结果 |
| --- | --- |
| 客户端自助登记 | 为当前受控 AP 的设备指派同名或新身份；不解除黑名单，不改白名单、出口；已登记时重复提交不改名 |
| 管理员指派身份 / 创建新身份 | 关联已有身份或新身份；黑名单继续优先 |
| 解除身份指派 | 清空归属；有白名单仍可免登记，否则按全局未登记策略处理 |
| 加入白名单 | 增加免登记资格；身份、黑名单、出口均保留 |
| 取消白名单 | 有身份时仍已登记；无身份时变为未登记；黑名单不受影响 |
| 普通拉黑（接口值 `L1`） | 阻断网络，保留身份、白名单和出口以便解封；不承诺断开 WiFi 关联 |
| 无线持久禁连（接口值 `L2`） | 普通拉黑之外，在 AP 的 MAC 过滤中增加门户拥有的条目并重载无线；可能导致同 AP 客户端短暂断线 |
| 解封 | 清除黑名单和门户添加的无线禁连；按保留的身份、白名单、出口恢复 |
| 设置指定出口 / 恢复正常出口 | 仅适用于已登记或白名单且未被拉黑的设备；普通模式仍遵守系统已有策略 |
| 移除设备记录（`forget`） | 删除设备的归属、白名单、黑名单、出口、标签和备注，并清理门户拥有的无线禁连；身份对象本身保留；设备回到未登记策略；独立观察历史保留 |
| 身份改名、合并、拆分 | 调整归属展示；不借此解除黑名单或出口限制；仅无设备引用的身份可以删除 |
| 修改标签、备注、页面文案 | 不改变准入状态 |
| 允许卸载 / 要求关闭卸载 | 改变门户的启用检查与兼容策略；不改变身份、白名单或出口，也不修改系统加速开关 |

若设备被管理员原有无线 MAC 过滤阻止，门户解封不会删除那条外部规则。原有无线白名单模式与持久禁连不兼容，操作会明确拒绝。

## 命令行示例

以下 MAC 和姓名仅为示例；使用设备自己的值。LuCI 调用同一管理入口。

```sh
/etc/portal/portal-admin split 02:00:00:00:00:01 示例用户
/etc/portal/portal-admin whitelist 02:00:00:00:00:01 1
/etc/portal/portal-admin setegress 02:00:00:00:00:01 wifi-only
/etc/portal/portal-admin block 02:00:00:00:00:01 '管理员暂停访问' L1
/etc/portal/portal-admin unblock 02:00:00:00:00:01
/etc/portal/portal-admin assign 02:00:00:00:00:01 ''
/etc/portal/portal-admin setegress 02:00:00:00:00:01 normal
/etc/portal/portal-admin forget 02:00:00:00:00:01
```

无需为普通管理操作手动操作 nft 集合或直接写 UCI。公共入口使用同一把写锁和独立 UCI 暂存目录，避免并发登记与 LuCI 管理互相覆盖。

## 离线历史管理

离线观察条目不属于授权凭据，未登记设备仍受全局策略约束。离线加白、指派或拉黑复用相同写入口；在线与地址证据、IPv6 辅助后缀规则见 [设备观察与历史](设备观察与历史.md)。
